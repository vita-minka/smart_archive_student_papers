# Поведение API (проект)

Контракты `api.yaml` и `search-api.yaml` описывают **будущий** HTTP API; работающего сервера в точке 1 нет.

## Загрузка
`POST /api/v1/documents` принимает PDF и метаданные; проверяет размер, формат, разрешение на размещение, создаёт запись со статусом `processing`. Некорректные данные → 400/422; недоступные права → 403. После обработки документ получает `ready` или `failed`.

## Вопрос
`POST /api/v1/ask` принимает query, filters и top_k; backend вызывает `/v1/search`, передаёт контекст LLM и возвращает answer, sources, status. При отсутствии результатов status=`insufficient_context`, sources=[]; модель не придумывает источники.

## Доступ
Сервис проверяет авторизацию и доступ к документам до retrieval. Права в mock-интерфейсе не являются реальной защитой.

## Ошибки
Единая структура `{code, message}`; клиент показывает понятное сообщение, не раскрывает приватные пути и содержимое закрытых документов.

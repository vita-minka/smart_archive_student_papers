# Спецификация поиска BM25 и RAG

## Требование НИРС
Самостоятельно реализовать **поисковый индекс на основе BM25**. Использование готовых поисковых индексов запрещено. Библиотеки извлечения текста PDF и лемматизации допустимы; выбор предобработки требуется обосновать.

## Корпус
Разрешённые PDF-курсовые, дипломы и статьи. Документ имеет стабильный ID, название, автора, год, тип, источник и условия доступа. Текст делится на фрагменты с привязкой к страницам. Оригиналы и метаданные не смешиваются с вымышленными mock-данными.

## Предобработка
1. Извлечь текст по страницам; для сканов без текстового слоя — понятная ошибка (OCR вне MVP).
2. Нормализовать пробелы, регистр и Unicode; сохранять исходный текст для цитирования.
3. Токенизировать слова (первоначально Unicode-регулярное выражение); одинаковая процедура для запроса и корпуса.
4. Лемматизация русского текста — экспериментальный вариант с библиотекой; сравнить качество с базовой токенизацией. Стоп-слова удалять только после проверки влияния на метрики.
5. Разбить текст на chunks (например, 150–250 слов, перекрытие 30–50); точные значения подобрать на dev-наборе.

## Собственный индекс
Хранить `postings[term] -> (chunk_id, tf)`, `df[term]`, `length[chunk_id]`, `avgdl`, `N`. При обновлении корпуса индекс пересобирается или инкрементально корректируется с контролем версии.

## BM25
`idf(t) = ln(1 + (N - df(t) + 0.5)/(df(t) + 0.5))`

`score(q,d) = sum_t idf(t) * tf(t,d)*(k1+1) / (tf(t,d)+k1*(1-b+b*len(d)/avgdl))`

Начальные параметры: `k1=1.5`, `b=0.75`. Фильтры по году, типу и доступу применяются **до** формирования top-K. При равных score сортировать по стабильному ID.

## Единица релевантности и метрики
Ранжируются **фрагменты**, но для обязательного gold используется **document_id**: в top-5 документов берём первые пять уникальных document_id из ранжированных разрешённых фрагментов. Это исключает ситуацию, когда пять фрагментов одной работы искусственно завышают качество. MRR считается по позиции первого релевантного документа.

## Генерация
Top-K фрагментов передаются LLM с метаданными. Модель должна отвечать только по контексту; ссылки разрешены только на полученные chunk_id. При отсутствии оснований выводить «В доступном корпусе недостаточно сведений». Сходство тем не означает плагиат.

## Ограничения
BM25 — лексический поиск, сам по себе **не семантический**. Семантический поиск эмбеддингами — возможное расширение после выполнения обязательного BM25, а не замена индекса.

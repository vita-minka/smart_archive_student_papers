# КТ2 — подготовка 20 размеченных вопросов и корпуса

Репозиторий **не включает реальные студенческие работы**. Здесь нет и не должно быть придуманных релевантных ссылок. Чтобы получить настоящие значения Recall@5/MRR, нужен корпус из разрешённых документов, минимум три действительно релевантных документа к каждому вопросу, и экспертная разметка.

## Запуск с реальными документами (Mac, из корня проекта)

1. Создайте `corpus/documents/` и положите туда **разрешённые к использованию** PDF, TXT или MD-файлы. Для PDF с текстовым слоем установите библиотеку: `python3 -m pip install pymupdf`. Для TXT/MD установка не нужна. Сканам PDF без текстового слоя нужен отдельный OCR.
2. Импортируйте: `python3 -m benchmark.prepare import`. Получите `corpus/chunks.jsonl`, `corpus/manifest.json`, `corpus/document_ids.csv`.
3. Сгенерируйте таблицу вопросов: `python3 -m benchmark.prepare worksheet`. Таблица `benchmark/questions_to_fill.csv` содержит 20 **пустых** строк (q01–q10 dev, q11–q20 holdout). Если файл уже существует, он не будет перезаписан.
4. Заполните `query` (содержательные, разнообразные и не скопированные дословно из PDF) и `gold_document_ids` (минимум три подтверждённых ID, разделённых `;`, из `corpus/document_ids.csv`). `filters` по умолчанию `{}`. Разметка **экспертная**, не результат работы BM25. Используйте `annotation_note` для комментария, почему документы релевантны. Если для вопроса нет трёх документов, измените вопрос или дополните корпус, но не подставляйте нерелевантные.
5. Проверьте и конвертируйте таблицу: `python3 -m benchmark.prepare export`.
6. Выполните полный запуск: `python3 -m benchmark.run --corpus corpus/chunks.jsonl --questions benchmark/questions.jsonl --split all --output benchmark/results-real.json`.
7. Для проверки вне разработки: `python3 -m benchmark.run --corpus corpus/chunks.jsonl --questions benchmark/questions.jsonl --split holdout --output benchmark/results-holdout.json`.

Каждый запуск строит индекс из текущих `chunks.jsonl`; измеряется только время BM25 retrieval. Параметры `k1` и `b` подбирают только на `dev`. `holdout` не использовать для подбора. Результаты нельзя выдавать за проверку LLM или сканирования PDF.

### Проверка исходных данных

`corpus/document_ids.csv` содержит ID/заголовки; `corpus/manifest.json` содержит SHA-256 исходных файлов. Не публикуйте закрытые студенческие работы, личные данные и файлы без прав использования.

Если необходимо измерить p50 latency и отдельно полное время LLM-ответа, это другая интеграционная проверка: текущий benchmark меряет только BM25. Среднее и p95 присутствуют в отчёте. Для надёжных latency цифр требуется значительно больше повторов и контроль окружения.

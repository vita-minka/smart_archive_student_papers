# ThesisHub — интеллектуальная база знаний студенческих и научных работ

Веб-приложение «Умный архив студенческих работ»: поиск по корпусу курсовых, выпускных квалификационных работ и научных статей с последующим формированием ответов LLM на основе найденных источников.

## Тема и пользователь

**Тема:** интеллектуальная база знаний студенческих и научных работ с поиском релевантных фрагментов PDF-документов и ответами на вопросы с указанием источников.

**Пользователи:**
- студент, который ищет похожие темы, методы и исследования для собственной работы;
- преподаватель или научный руководитель, который сравнивает тематики и анализирует предшествующие исследования.

Пример задачи: «Какие работы были посвящены RAG в 2024 году?» Пользователь загружает или выбирает документы, задаёт вопрос, получает подборку релевантных фрагментов и ответ со ссылками на названия работ и страницы. Система помогает находить тематически похожие исследования, но не выносит автоматическое заключение о плагиате.

## Запуск прототипа

Открыть `prototype/chat.html` в современном браузере. Дополнительные страницы: `prototype/auth.html` и `prototype/profile.html`. Сервер и установка зависимостей не нужны.

**Важно:** прототип использует демонстрационные данные. Он не выполняет реальный поиск, не загружает PDF на сервер и не обращается к LLM.

## Архитектура планируемой системы

| Компонент | Назначение |
| --- | --- |
| Frontend | Загрузка работ, поисковая строка, результаты, чат, отображение источников |
| Backend | API, метаданные документов, хранение, вызов поиска и модели |
| Search | Предобработка текста, обратный индекс и самостоятельно реализованный BM25 |
| LLM | Формирование ответа исключительно на основе найденного контекста |
| Corpus | PDF-файлы, извлечённые тексты, фрагменты и метаданные |
| Benchmark | Оценка Recall@5, MRR и времени ответа |

Основной путь: **PDF → извлечение текста → фрагментация и предобработка → собственный индекс BM25 → top-K фрагментов → LLM → ответ с источниками**.

Методические указания НИРС требуют самостоятельно реализовать поисковый индекс BM25; готовые поисковые индексы использовать нельзя. Для каждого тестового запроса необходимо определить не менее трёх релевантных документов. Проектный benchmark предусматривает 20 вопросов, Recall@5, MRR и измерение времени ответа.

## План развития

1. **Контрольная точка 1:** спецификации, структура GitHub и демонстрационный прототип.
2. **Следующий этап:** реальный корпус, самостоятельный BM25, проверка поисковой выдачи на размеченных вопросах.
3. **Интеграция:** обработка PDF, backend, frontend и LLM; оценка качества и времени ответа.

Актуальное состояние следует сверять с исходным кодом и результатами проверок. Наличие спецификации не означает, что описанный модуль уже реализован.
